## О проекте

Веб-приложение для обмена текстовыми сообщениями в реальном времени, построенное на базе гибридной модели сетевого взаимодействия (**REST API** + **WebSockets**) и развернутое в изолированной микросервисной среде с использованием **Docker** и **Docker Compose**.

### Основные возможности
* **Аутентификация и авторизация:** регистрация пользователей, хэширование паролей (`bcrypt`) и выдача JWT-токенов доступа (OAuth2 Password Flow).
* **Обмен сообщениями в реальном времени:** полнодуплексная передача сообщений через протокол WebSocket с автоматической загрузкой последних 50 сообщений истории при подключении.
* **Синхронизация состояния:** автоматическое обновление списка пользователей онлайн и системные уведомления о входе/выходе участников.
* **Панель администратора:** просмотр активных пользователей, реактивное удаление сообщений у всех подключенных клиентов без перезагрузки страницы и перманентная блокировка (бан) нарушителей с принудительным разрывом активного WebSocket-соединения.
* **Адаптивный интерфейс:** одностраничный веб-клиент (HTML5 + CSS3 + Vanilla JS), корректно отображающийся как на ПК, так и на мобильных устройствах.

## Архитектура и сетевая топология

Система состоит из трех изолированных Docker-контейнеров, объединенных во внутреннюю мостовую сеть `chat_network`:

1. **`nginx` (API-шлюз):** единственная точка входа из внешней сети (порт `80`). Проксирует обычные HTTP-запросы на бэкенд и выполняет обновление соединения (`Upgrade: websocket`) для маршрута `/ws/`.
2. **`web` (Сервер приложения FastAPI):** обрабатывает бизнес-логику, валидирует токены и управляет пулом активных сокетов в оперативной памяти (`ConnectionManager`). Доступен только внутри сети `chat_network` на порту `8000`.
3. **`db` (СУБД PostgreSQL 15):** хранит учетные записи (`users`) и историю сообщений (`messages`). Изолирована внутри сети `chat_network` (порт `5432`), данные сохраняются на хост-машине через именованный том `pgdata`.

## Запуск и развертывание

### Предварительные требования
* Установленный **Docker Engine** и **Docker Compose**.

### Пошаговая инструкция

1. **Клонируйте репозиторий и перейдите в директорию проекта:**
   ```bash
   git clone <url_репозитория>
   cd <папка_проекта>
   ```

2. **Соберите образы и запустите контейнеры в фоновом режиме:**
   ```bash
   docker-compose up --build -d
   ```
   *Таблицы `users` и `messages` создаются автоматически при старте приложения через механизм `lifespan` в FastAPI.*

3. **Проверьте статус запущенных сервисов:**
   ```bash
   docker-compose ps
   ```
   Все три контейнера (`nginx`, `web`, `db`) должны находиться в состоянии `Up` (а `db` — `healthy`).

4. **Откройте приложение в браузере:**
   * Веб-интерфейс чата: `http://localhost/`
   * Интерактивная документация API (Swagger UI): `http://localhost/docs`

### Полезные команды управления

* Просмотр логов серверного приложения:
  ```bash
  docker-compose logs -f web
  ```
* Остановка и удаление контейнеров (с сохранением данных в БД):
  ```bash
  docker-compose down
  ```
* Полная очистка контейнеров и тома базы данных:
  ```bash
  docker-compose down -v
  ```

## Спецификация API

| Метод / Протокол | Эндпоинт | Описание | Доступ |
| :--- | :--- | :--- | :--- |
| `GET` | `/` | Получение HTML-страницы веб-клиента | Публичный |
| `POST` | `/register` | Регистрация нового пользователя (`username`, `password`, `is_admin`) | Публичный |
| `POST` | `/token` | Аутентификация и получение JWT-токена (`Form-Data`) | Публичный |
| `DELETE` | `/messages/{message_id}` | Удаление сообщения из БД и рассылка команды удаления в чат | Только админ (JWT) |
| `POST` | `/admin/ban/{target_user_id}` | Перманентная блокировка пользователя и разрыв его WS-сессии | Только админ (JWT) |
| `WS` | `/ws/chat/?token=<JWT>` | Полнодуплексный канал обмена сообщениями в реальном времени | Авторизованный (JWT) |
